# 闸口事件湖仓台

码头闸口扫描先落在贴源层，原文照收。建层员选定业务日，按事件字典把扫描收成明细层：进闸、出闸、倒箱。字典里没有的事件码、箱号不合法或时间读不出的扫描留在剔除清单，不进明细。

贴源原文里还常多出字典外的键（像 `seal`、`truck`）。这些键不能有的日子丢掉、有的日子扩进明细：收成前先定一套扩列办法，定下来就钉住，全湖沿用。

这里不管堆存量，只处理扫描事件怎么分层。

## 扩列

扩列办法只能二选一：

| 办法 | 取值 | 含义 |
|------|------|------|
| 丢掉字典外的键再入库 | `drop` | 新键不扩进明细，只在扩列列表里记丢掉次数 |
| 把新键扩进明细列 | `expand` | 新键在 `dwd_move` 各占一列（`ext_<键名>`），原文值照抄进去 |

规矩：

- 办法一经选定即钉住，本日不得更换；钉住后全湖沿用同一套，不会有的日子丢掉、有的日子扩进。
- 扩列尚未钉住时，当天只要有带新键的扫描，就不准收成。
- 收成时带上的办法跟扩列设置不合，记**扩列办法偏了**，新键不落库。
- 两名仓管同时给同一新键扩列，同源加锁后只收下与扩列设置相符的写法，另一路记**扩列争用**。
- 键名为空的原文键不进新键队列，也不参与收成。

页面上四块当场改动：**扩列设置**（选办法、看钉住人）、**扩列列表**（新键名、丢掉次数、扩进次数、办法名）、**新键队列**（每条新键的去向）、**字段详情**（原文键对明细列，能看出是丢掉了还是扩进了）。

## 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/dates` | 业务日清单，带未定新键数 |
| GET | `/api/dates/<date>` | 贴源、明细、剔除、新键队列、字段详情、扩列设置 |
| POST | `/api/dates/<date>/build` | 收成明细；可带 `{"policy": "drop"｜"expand"}` |
| POST | `/api/dates/<date>/land` | 落一条贴源原文，新键当场进队列 |
| GET/PUT | `/api/expand/settings` | 看 / 钉住扩列办法 |
| GET | `/api/expand` | 扩列列表、新键队列、争用、偏了 |
| GET | `/api/expand/list` | 扩列列表 |
| POST | `/api/expand/keys/<key>/expand` | 手动给同一新键扩列 |
| GET | `/api/dates/<date>/fields` | 字段详情 |
